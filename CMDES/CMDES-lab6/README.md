# Комп'ютерний практикум №6 — «Застосування алгоритму стохастичної мережі Петрі для реалізації моделей дискретно-подійних систем»

Моделі реалізовано бібліотекою **PetriObjModelPaint** (І. В. Стеценко,
[github.com/StetsenkoInna/PetriObjModelPaint](https://github.com/StetsenkoInna/PetriObjModelPaint), реліз 2.8.2):
мережі побудовано в її графічному редакторі, імітація — класом `PetriSim` у моделі `PetriObjModel`.

## Пакет файлів мереж Петрі

Для кожної мережі в `nets/`:

| Файл | Зміст |
|---|---|
| `task.txt` | текст завдання |
| `net.png` | зображення мережі Петрі з редактора |
| `net.pnml` | мережа у форматі PNML |
| `method.txt` | мережа у вигляді Java-методу (Save net as method) |

`nets/1_conveyor` — конвеєр (завдання 1 практикуму 5), `nets/2_fridges` — запаси холодильників
(завдання 4 практикуму 5), `nets/3_servers` — головний і допоміжний сервери зі спільною БД.

## Програми

| Файл | Зміст |
|---|---|
| `src/Nets.java` | методи мереж із `method.txt`; параметри експериментів винесено в аргументи |
| `src/Sim.java` | запуск мережі: `PetriSim` у моделі `PetriObjModel` |
| `src/Task1Conveyor.java` | 1: конвеєр і його верифікація |
| `src/Task2Fridges.java` | 2: запаси холодильників і верифікація |
| `src/Task3Servers.java` | 3: час обробки запиту на серверах |
| `run.bat` | запуск задачі |
| `report/` | звіт `Звіт_КП6.docx` / `.pdf` (зокрема рівняння мережі задачі 3) |

## Запуск

Потрібні Java 23+ і редактор PetriObjModelPaint (його jar використовується як бібліотека).
`run.bat` шукає його в `%USERPROFILE%\Downloads\PetriObjModelPaint\app\petri-swing-ui-windows.jar`;
інший шлях можна задати змінною `PETRI_JAR`.

```bash
run.bat Task3Servers
```

Числа від запуску до запуску трохи відрізняються: генератор бібліотеки (`Math.random`) не
ініціалізується фіксованим значенням.

## Основні результати

* **Конвеєр**: при зміні інтенсивності надходження λ середня кількість зайнятих пристроїв дорівнює λ·tобр,
  час перебування деталі в системі за формулою Літтла збігається з підрахованим через переміщення.
* **Холодильники**: зміна контрольного рівня, точки замовлення і періоду перегляду змінює запас і втрати
  в очікуваному напрямку.
* **Сервери**: середній час обробки запиту ≈ 93 мс на головному і ≈ 158 мс на допоміжному сервері
  (≈ 113 мс у середньому); при малому навантаженні він наближається до 85 і 105 мс — часу обчислення
  і запису в БД.
